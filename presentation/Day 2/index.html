Why .map() is used in React

  • In React, you rarely manually create repetitive HTML. Instead, we use JavaScript arrays and .map() to generate lists dynamically.
  • .map() iterates through an array and returns a JSX element for each item.
  • Example analogy: Think of a bakery conveyor belt – each item (JSX) is created from a recipe (array item).

Why Keys Matter ?

  • Keys help React identify which items changed, were added, or removed.
  • Without keys, React might re-render the entire list unnecessarily, causing performance issues or even bugs.
  • Keys must be unique among siblings and ideally stable across renders.
  • Example: Using index as a key is okay for static lists but not for dynamic lists where items may move or be deleted.

💡 Let's see what happens without proper keys

Understanding Keys: Index vs Unique ID

What happens when you use array index as key?

When you use the array index as a key, React identifies each element by its position in the array, not by what it actually contains.

Array with indexes:
[0] → Buy Eggs
[1] → Buy Milk
[2] → Buy Bread

The Problem with Index Keys

🐛 What goes wrong when list items are deleted?

If you delete an item from the middle of the list, all items after it shift up and get new indexes.

Before deleting "Buy Milk":
[0] → Buy Eggs
[1] → Buy Milk 🗑️
[2] → Buy Bread
After deleting:
[0] → Buy Eggs
[1] → Buy Bread ← Changed from [2] to [1]!

React thinks: "The item at index [1] changed from 'Buy Milk' to 'Buy Bread', so I'll re-render it but keep its old state (like input values)!"

The Solution: Use Unique IDs

✅ Unique IDs stay with each item

Use unique IDs that stay with each item regardless of its position. When an item is deleted, React knows exactly which one is gone.

Before deleting "Buy Milk":
key={101} → Buy Eggs
key={102} → Buy Milk 🗑️
key={103} → Buy Bread
After deleting:
key={101} → Buy Eggs
key={103} → Buy Bread ← Still key={103}, just moved up!

React knows: "key={102} was removed, key={103} is still the same item, just preserve its state!"

Best Practices for Keys

✅ Do's

  • Use unique IDs from your data (from API or database) 
    key={item.id}
  • Ensure keys are stable across renders (don't change unless the item is truly new)
  • Use index as key ONLY for static lists that never change order or get filtered

❌ Don'ts

  • Avoid random numbers (defeats React's diffing) 
    key={Math.random()} // ❌ Wrong!
  • Don't use array index for lists where items can be added, removed, or reordered
  • Don't skip keys in lists - React will show a warning in the console 
    // ❌ This will trigger a warning:
{items.map(item => <li>{item}</li>)}

// ✅ Always provide a key:
{items.map(item => <li key={item.id}>{item}</li>)}

    Console warning: "Warning: Each child in a list should have a unique 'key' prop."

Conditional Rendering

What is conditional rendering?

Conditional rendering is the ability to show or hide components or elements based on certain conditions (state, props, or data).

It is similar to if/else statements in programming but adapted for JSX.

Why Conditional Rendering Matters

  • Better UX: Shows context-sensitive content that's relevant to the user's current state
  • Performance: Avoids unnecessary DOM elements and reduces render load
  • Dynamic UI: Makes your interface responsive to user state and interactions

Ternary Operator (? :)

When to use it

Use the ternary operator when you need to choose between two options.

Syntax: condition ? renderThisIfTrue : renderThisIfFalse

Ternary Operator - Example

function LoginButton({ isLoggedIn }) {
  return (
    <button>
      {isLoggedIn ? 'Logout' : 'Login'}
    </button>
  );
}

// If isLoggedIn is true → shows "Logout"
// If isLoggedIn is false → shows "Login"

Logical AND (&&)

When to use it

Use the logical AND operator when you want to render something only if a condition is true.

Syntax: condition && renderThisIfTrue

Logical AND - Example

function Notification({ hasMessages }) {
  return (
    <div>
      {hasMessages && (
        <span className="badge">
          You have new messages!
        </span>
      )}
    </div>
  );
}

// If hasMessages is true → shows the badge
// If hasMessages is false → shows nothing

Ternary vs Logical AND

When to use which?

✅ Use ? :
  • When you have TWO alternatives
  • Show A or show B
  • Need an "else" case
✅ Use &&
  • When you have ONE option
  • Show something or nothing
  • No "else" needed

Ternary vs Logical AND - Examples

// ✅ Good: Two options → use ternary
{isLoggedIn ? <Dashboard /> : <LoginForm />}

// ✅ Good: One option → use &&
{isPremium && <PremiumFeatures />}

// ❌ Awkward: Don't use ternary when you only want one option
{isPremium ? <PremiumFeatures /> : null}

What is the Virtual DOM?

  • React maintains a Virtual DOM, a lightweight copy of the real DOM stored in memory.
  • Think of it as a blueprint of the UI React can compare quickly without touching the actual browser DOM.
💡 Visual Concept
🌳
Real DOM
(Heavy)
↔️
📄
Virtual DOM
(Lightweight)

How React Updates the UI Efficiently

When a component state or prop changes:

  1. React creates a new Virtual DOM tree
  2. Compares it to the previous Virtual DOM (this is called diffing)
  3. Only updates the actual DOM elements that changed, instead of re-rendering everything

Analogy: Instead of repainting an entire wall, React only touches the bricks that are cracked.

🔄 The Process
State Change → New Virtual DOM → Diff → Minimal DOM Update

Importance of Keys in Reconciliation

  • Keys allow React to match elements between renders, making diffing fast and accurate
  • Without keys, React may re-render the whole list even if only one item changed

Reconciliation in Action

Example Concept

If a list of 10 items changes only the 3rd item,
React updates only that element, not all 10.

Why Hooks Exist ?

The Problem Before Hooks

Before React 16.8, state and lifecycle features were only available in class components.

Functional components were "stateless" - they could only receive props and return JSX.

The Solution: Hooks

Hooks let us use state, effects, and other React features in functional components, making them simpler and more powerful.

Rules of Hooks

The Rules

  1. Call Hooks at the top level: Don't put Hooks inside loops, conditions, or nested functions. This ensures that Hooks are called in the same order every render.
  2. Call Hooks only in React functions: Only inside functional components or custom hooks.
  3. Hooks order must stay the same: Changing order will break React's internal tracking of state and effects.

Common mistakes

  • Calling useState inside if statements.
  • Using Hooks inside non-component functions.
❌ Wrong 
if (loggedIn)
  const [state, setState] = useState();
✅ Right 
const [state, setState] = useState();
if (loggedIn) { ... }

useEffect for Side Effects

What is a side effect?

Any operation that interacts outside the component or affects something outside its scope.

Examples: Fetching data, timers, subscriptions, manual DOM manipulation.

When does useEffect run?

  • After the component renders.
  • With dependencies, it runs only when those dependencies change.
  • Empty dependency array [] → runs once after first render (similar to componentDidMount in class components).

Cleanup function

  • Return a function from useEffect to clean up resources like intervals, subscriptions, or event listeners.
  • Prevents memory leaks.

💡 Show example with timer: effect sets interval → cleanup clears interval

Example: Clock with useEffect

🎯 What this example demonstrates

  • useEffect with setInterval: Updates the time every second
  • Empty dependency array []: Effect runs once after initial render, then the interval keeps running
  • Cleanup function: Returns a function that clears the interval when component unmounts
  • Prevents memory leaks: Without cleanup, the interval would keep running even after component is removed
Next: Let's see the code implementation →

Example: Clock with useEffect - Code

JavaScript/JSX 
import { useState, useEffect } from "react";

export default function Clock() {
  const [time, setTime] = useState(new Date());

  useEffect(() => {
    const timer = setInterval(() => {
      setTime(new Date());
    }, 1000);

    return () => clearInterval(timer);
  }, []);

  return (
    <h1>{time.toLocaleTimeString()}</h1>
  );
}
CSS 
h1 {
  font-size: 1rem;
  color: #333;
}

Custom Hooks (30 min)

What is a custom hook?

  • A JavaScript function that starts with use and reuses component logic.
  • Can use other hooks inside it (useState, useEffect, etc.).

Why use custom hooks

  • Avoid repeating code.
  • Separate logic from UI.
  • Makes code cleaner and easier to test.

Example

useFetch encapsulates data fetching logic, so any component can just call const { data, loading } = useFetch(url).

💡 Show example: component without custom hook (repeated fetch code) vs component with custom hook

Example: useFetch Custom Hook

import { useState, useEffect } from "react";

export function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch(url)
      .then((res) => res.json())
      .then((json) => setData(json))
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading };
}

useRef for Mutable References & DOM Access

What is useRef?

  • A hook that holds a mutable object whose .current property persists across renders.
  • Can store DOM elements or mutable values.

Use cases

  • DOM access: Focus input, scroll to element, measure element size.
  • Mutable storage: Store previous state or timer ID without triggering re-renders.

Important rules

  • Updating .current does not trigger a render.
  • Useful for performance-sensitive operations.

💡 Show visual: component renders, useRef stores a DOM element → manipulate it without re-rendering

Example: Focus Input with useRef

JavaScript/JSX 
import { useRef } from "react";

function FocusInput() {
  const inputRef = useRef();

  const handleFocus = () => {
    inputRef.current.focus();
  };

  return (
    <div className="focus-container">
      <input
        ref={inputRef}
        type="text"
        placeholder="Type here..."
      />
      <button onClick={handleFocus}>
        Focus Input
      </button>
    </div>
  );
}
CSS 
.focus-container {
  display: flex;
  gap: 0.5rem;

  input {
    padding: 0.5rem;
    border-radius: 4px;
    border: 1px solid #ccc;
  }

  button {
    padding: 0.5rem 1rem;
    background: #0070f3;
    color: white;
    border: none;
    border-radius: 4px;
  }
}
