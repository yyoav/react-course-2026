The Problem: Prop Drilling

Global State Management in React Context API Zustand When to use what

What is "prop drilling"?

<App>
  <Layout user={user}>
    <Sidebar user={user}>
      <Avatar user={user} />
    </Sidebar>
  </Layout>
</App>

👉 Passing props through components that don't need them.

Why it's bad?

  • Hard to maintain
  • Breaks easily
  • Makes components tightly coupled
  • Painful refactoring

Solution Categories

  • Context API (built-in)
  • External state libraries (Zustand, Redux, etc.)

What is Context?

👉 A way to share data globally without props

Best for:

  • Theme (dark/light)
  • Auth user
  • Language / locale

Basic Example

createContext
const ThemeContext = createContext("light");
Provider
<ThemeContext.Provider value="dark">
  <App />
</ThemeContext.Provider>
Consuming Context
const theme = useContext(ThemeContext);
createContext Provider useContext

Important Concept

⚠️ Context is NOT a state manager

👉 It only shares values

👉 You still need useState or useReducer

🧪 Exercise 1 — Theme Toggle (Context)

→ live coding

🎯 Goal

Create a global theme system:

  • Light / Dark
  • Toggle from any component

📋 Requirements

Create ThemeContext

Store:

  • theme
  • toggleTheme()

Use in:

  • Header
  • Content

Solution

import { createContext, useContext, useState } from "react";

const ThemeContext = createContext(null);

export const ThemeProvider = ({ children }) => {
  const [theme, setTheme] = useState("light");

  const toggleTheme = () =>
    setTheme((prev) => (prev === "light" ? "dark" : "light"));

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
};

Usage

const Button = () => {
  const { theme, toggleTheme } = useTheme();

  return (
    <button onClick={toggleTheme}>
      Current: {theme}
    </button>
  );
};

🧠 Teaching Notes

Emphasize:

  • Custom hook (useTheme) is BEST PRACTICE
  • Avoid deeply nested providers
  • Re-renders happen when value changes
